# 캡션과 라벨 규칙

## 캡션 (figcaption)

- 그림이 증명하는 결론 한 문장. 그림 묘사(`A와 B의 구조`) 금지
  - ✗ `LLM 서비스의 요청-응답 구조`
  - ✓ `모델은 함수 호출을 출력할 뿐이고 실제 실행은 런타임이 맡는다`
- 40자 안팎. 넘으면 결론을 하나만 남긴다
- 원문 문체(평서체/경어체)를 따른다
- 원문에 없는 주장 금지

## 단계 캡션 (createDemo)

- 2~4개. 각 단계에서 독자가 새로 알게 되는 사실 한 문장
- 앞 단계는 사실을 쌓고, 마지막 단계가 결론. 첫 단계부터 결론을 말하지 않음
  - 예: ① 두 서버에 요청이 40건씩 들어온다 → ② 평균 응답 시간은 둘 다 120ms다 → ③ 가장 느린 1%는 약 6배 차이다
- 캡션이 가리키는 것은 그 단계가 끝날 때 그림에 보여야 함
- 번호(①②③)는 런타임이 붙이므로 쓰지 않음. 예시 데이터 표시는 첫 단계 캡션에

## 요소 라벨

- 명사 1~3어절 (`주방`, `주문서`, `양념 추가`)
- 화살표 라벨은 오가는 것의 이름 (`주문`, `음식`), 동작 설명 문장 금지
- `status`는 진행형 명사구 (`조리 중`, `생성 중`)
- 같은 대상은 본문/라벨/캡션에서 같은 단어로 부른다
