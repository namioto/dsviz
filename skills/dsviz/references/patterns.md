# 설명 구조 카탈로그

기본은 `createDiagram`. "단계별 결론" 열이 ✓인 구조는 앞 단계에서 독자가 먼저 믿게 되는 것이 보여야 결론이 서므로 `createDemo`를 쓴다. 독자가 직접 조작하는 실험은 `createLab`.

|---|---|---|---|---|
| `system-map` | 구성도 | 구성 요소와 요청/데이터 흐름 | box, arrow(`offset`으로 왕복) / grow, travel, status | |
| `composition` | 구성 비교 | 같은 틀에 들어가는 내용이 방식마다 어떻게 다른지 | box(`labelAt: "top"`) 여러 개 + 안쪽 box/chip / fade | |
| `loop` | 반복 루프 | 조건을 만족할 때까지 도는 과정과 빠져나오는 지점 | loop, chip, arrow / grow, cycle, pulse | |
| `selection` | 선택 | 여러 후보 중 상황에 맞는 것을 고름 | box 여러 개, arrow 하나만 `focus` / grow, 고른 뒤 `highlight`, pulse | |
| `process-flow` | 과정 흐름 | 단계 순서와 막히는 지점 | box 가로 나열, arrow / grow 순서대로, travel | |
| `cascade` | 연쇄 전파 | 하나의 변화가 다음 요소로 번짐 | box/dot 그물, arrow / grow를 시차 두고 연쇄, pulse | |
| `capacity-queue` | 용량과 대기열 | 처리량을 넘으면 쌓이는 줄 | box(처리기), dot 줄 / fade 시차, status. 처리기 수나 도착 속도를 바꿔 보게 하려면 createLab | |
| `timeline-review` | 타임라인 회고 | 결과 전에 이미 있던 신호 | line(시간축), dot, chip / fade 순서대로, pulse | |
| `before-after` | 전후 비교 | 사건 하나를 기준으로 달라진 점 | 같은 구성 두 벌 나란히, 차이만 `focus` / fade | |
| `trend` | 추이 | 시간에 따른 변화, 여러 시리즈 비교 | chart + lineSeries/areaSeries, refLine, 데이터 좌표 chip / grow, highlight | |
| `compare-bars` | 항목 비교 | 항목별 크기 차이, 가장 큰/작은 항목 | chart + bars(`labels`), 답 막대만 역할 색 / `ids`+`stagger` grow, highlight | |
| `summary-trap` | 요약값의 함정 | 요약값은 같은데 분포가 다름 | 같은 x/y 범위의 차트 두 개를 위아래(분포 모양 비교) 또는 좌우: 숫자형 x bars(히스토그램) + refLine(평균/백분위) / refLine grow 먼저, 막대 stagger grow | ✓ |
| `shape-grid` | 패턴 비교 그리드 | 여러 모양을 나란히 놓고 구분 | 작은 chart 여러 개 + lineSeries, chip 제목 / grow | |
| `drift-vs-jump` | 서서히 변화와 급변 | 조금씩 쌓이는 변화와 한 번에 뛰는 변화 | 시리즈 두 개 + chip(실제 변화량) 또는 chart 두 개 / grow, highlight | |

## 차트 배치 기준

- `g.chart`의 x y w h는 그림 영역. 왼쪽 40 이상(y 눈금), 아래 24 이상(x 눈금, `xLabel`이면 44), 위 24 이상(`yLabel`), 오른쪽은 시리즈 끝 라벨 폭만큼 비움
- 차트 여러 개를 나란히 두면 y 범위(`yDomain`)를 같게 맞춰 높이를 비교할 수 있게 함
- 막대 차트는 0부터 시작(자동). 선/영역 차트에서 0이 아닌 범위를 쓰면 `yDomain`을 명시
- 시리즈 끝 라벨끼리 가까우면 런타임이 위아래로 벌리고, x 눈금 글자가 겹치면 하나 걸러 하나로 줄임. 수동 조정은 `labelDy`
- 크기가 크게 다른 시리즈를 한 차트에 두면 작은 시리즈의 변화가 평평해 보임. 그 왜곡 자체가 결론이면("눈에 안 띈다") 한 차트에 두고 칩으로 실제 변화량을 적고, 아니면 차트를 나눠 각자 y 범위를 씀
- 시리즈 일부 구간만 강조할 때는 시리즈를 나누지 않고 `g.segment`
- 곡선(`curve: "smooth"`)은 흐름과 추세가 결론일 때만. 점 하나하나의 값이나 급변 시점이 중요하면 직선(급변이 곡선으로 뭉개짐). 곡선이어도 `dots`로 실제 데이터 점을 보여주면 오해가 줄어듦
- 막대 끝 값 바로 위에 기준선 라벨이나 칩을 두지 않음. y 범위 최댓값이 가장 큰 막대와 같으면 라벨 자리가 없으므로 `yDomain`을 한 칸 넓힘

## 배치 기준

- 640 기준 폭에서 좌우 여백 20 이상, 요소 사이 간격 24 이상
- 흐름 방향은 원문 표현을 따름: "아래로 퍼진다", "상위/하위"처럼 위계를 말하면 데스크톱도 위 → 아래, 그 외 순서는 왼쪽 → 오른쪽. 모바일은 위 → 아래
- 캡션의 방향 표현(아래로/오른쪽으로)과 그림 방향을 맞춤
- 왕복 화살표는 같은 `offset` 값(예: `-30`)을 양쪽에 주면 진행 방향 기준으로 서로 반대편에 놓인다
- 박스 안에 다른 요소를 담으면 `labelAt: "top"`, 안쪽 요소의 위 끝은 박스 위 끝에서 50 이상 아래
- 요소 하나를 가리키는 라벨은 그 요소 바로 옆(간격 24 이내). 한 줄 전체를 가리키는 라벨(개수, 단계 이름)은 데스크톱에서 그 줄 왼쪽 바깥에 세로 중앙을 맞추고, 왼쪽 공간이 없으면 줄 바로 위 가운데
- 한 그림의 역할 색은 2~3개. 나머지는 neutral/muted
- 사물 모양(비행기, 건물, 화면)은 부품마다 box 하나로 조립하고 라벨은 부품 이름. 부품 사이 간격 8 이상, 실루엣보다 부품 구분이 읽히는 것을 우선
- 부품 위에 점(자국, 위치)을 찍을 때는 라벨 글자와 겹치지 않게 상자 모서리 쪽에 둠
- 차트 위 칩이 기준선과 겹치면 칩을 기준선 반대쪽으로 `dx`만큼 옮기고, 칩이 가리키는 점에 `dot`이나 `segment`를 둬 연결이 보이게 함

## sequence 타이밍 기준 (play 3000ms 기준)

- 단계 하나 0.25~0.45 구간, 다음 단계는 앞 단계 끝나기 0.05 전에 시작
- 화살표 끝의 대상은 등장 구간의 중간 지점이 화살표 도착 시점보다 앞서게 (예: 도착 0.62면 대상 `fade` 0.52~0.66)
- 같은 효과를 여러 요소에 차례로 주면 `ids` + `stagger` 사용
- 답(선택된 후보, 병목, 원인)을 처음부터 역할 색으로 칠하면 결론이 먼저 보임. 답은 `highlight`로 마지막 단계에 색을 입힘
- 마지막 단계는 0.95 이전에 끝냄 (hold 3초 동안 완성 그림 유지)
- 단계가 5개를 넘으면 `timing.play`를 늘리거나 그림을 나눈다
